# 项目经历 STAR 拆分

## 1. 霸王茶姬 GIS 智能选址系统(2025.01-2026.08)

- **S 背景**:霸王茶姬拓店选址依赖经验判断,缺少整合区域 AOI/POI、客流、商业热力的数据化决策工具。公司已有成熟产品平台可复用。
- **T 任务**:作为开发负责人,在现有平台上垂直扩展出面向该业务线的 GIS 选址模块,主导架构设计与核心功能落地。
- **A 行动**:

- 前端用 React + Leaflet 实现动态地图渲染,后端用 Spring Boot + PostgreSQL/PostGIS 接入新业务,保持标准化延伸。
- 对接并清洗高德的 POI 围栏、AOI 面状数据、实时客流和商业热力数据。
- 结合 Grid 格网切片,用热力图、聚合图量化客流和经济指标。
- 在 PostGIS 中增量构建 GiST 空间索引,优化海量坐标的几何查询效率。
- **R 结果**:服务于核心业务线的拓店决策,让业务方从"经验判断"转向"数据驱动"。

## 2. 企业内部知识库与聊天机器人(2026.05-2026.07)

- **S 背景**:公司产品框架文档缺失,模块说明难以落地,新员工和跨部门同事上手慢,重复沟通多。
- **T 任务**:独立设计并搭建企业级 RAG 问答系统,支持 Markdown、Swagger、Wiki 内容检索。
- **A 行动**:

- 设计 React → NestJS → LangChain → Qdrant 的完整 AI 链路,前端基于 Dify 编排。
- 设计异构文档 ETL 流程,用 LangChain 做切片和 Embedding 向量化。
- 用 Qdrant + 余弦相似度检索,提升文档与 API 的召回精准度。
- 基于 NestJS + SSE 实现无刷新连续对话,设计对话历史存储,并用 LLM 自动摘要对话。
- **R 结果**:上线后获团队正向反馈,减少了因文档缺失产生的重复沟通,成为新人了解产品架构的辅助工具。

## 3. 选址服务基础平台(2025.07-2026.05)

- **S 背景**:GIS 选址、门店拓展等上层业务都需要缓存、权限、动态查询、表单等通用能力,各业务重复建设、稳定性和扩展性不足。
- **T 任务**:独立主导设计通用技术底座,支撑上层选址业务。
- **A 行动**:

- **缓存**:设计接口化缓存组件,统一 Redis 序列化规范,用随机 TTL 防雪崩、空值缓存防穿透。
- **动态查询**:基于 SpEL 设计变量解析器,支持配置端灵活定义规则。
- **权限与元数据**:设计级联字典表和全局配置服务,重构菜单管理使其动态配置实时生效,实现页面/按钮/接口三级 RBAC(路由过滤 + JWT)。
- **动态表单**:采用"主表 + 字段配置表",用 PostgreSQL JSONB 存储异构数据。
- **R 结果**:为霸王茶姬 GIS 选址系统提供缓存、权限、动态查询等底层支撑;菜单权限动态配置、表单免 DDL 变更,显著降低运维和迭代成本。

## 4. 大型 MPA 项目构建性能优化(原文未标注时间)

- **S 背景**:公司大型 MPA 项目构建慢、产物体积臃肿。
- **T 任务**:独立主导构建工具链升级,同时优化构建速度和产物体积。
- **A 行动**:

- **构建工具切换**:从传统打包方案切换到 Rspack + SWC,采用 sass-embedded 和 SwcJsMinimizer。
- **依赖治理**:修正 dependencies / devDependencies 归属混乱的问题,降低生产依赖体积和安全风险。
- **分包优化**:重设 splitChunks 策略,用 minChunks 设公共包准入门槛,用 cacheGroups + priority 分层调优 React、jQuery 等库,隔离登录页与重型库。
- **监控体系**:引入 Rsdoctor 和 BundleAnalyzer,可视化依赖拓扑,快速定位冗余依赖。
- **R 结果**:生产构建速度提升 5 倍以上,全站首屏 JS 体积削减约 40%,提升研发效率和首屏体验。

## 5. 集团主数据接入平台(2025.01-2025.12)

- **S 背景**:集团上游系统下发用户、角色、区划、职位、菜单、部门、权限等主数据,数据源异构,消费链路扩展性差,分布式 MQ 调试和排查困难,认证体系也需升级。
- **T 任务**:重构主数据消费链路,实现异构数据源插拔式接入,同时落地 JWT 双 Token 与 OAuth 互信体系。
- **A 行动**:

- **架构**:用策略模式 + 工厂模式解耦数据的解析、清洗、分发。
- **日志**:基于 Spring AOP 统一收口日志,非侵入式分离 MQ 消费日志与系统运行日志。
- **调试**:设计 Controller 模拟测试接口,构建"请求→模拟下发→消费验证"闭环沙箱。
- **认证**:落地 AccessToken + RefreshToken 双 Token,用 Redis 管理 RefreshToken 生命周期,支持无感刷新和动态销毁;提供 OAuth 接口,支持三方 Token 互换。
- **R 结果**:新业务接入成本降低,分布式场景下排查和联调效率显著提升,在无感刷新的同时强化了系统安全性。

## 6. 赛百味 GIS 智能选址模块(2024.01-2024.12)

- **S 背景**:赛百味全国门店拓店选址,需要在现有 GIS 平台上采集候选点位、评估周边商圈,并衔接审批流程。
- **T 任务**:作为开发者,定制开发独立的"机会点"采集与分析模块。
- **A 行动**:

- 基于 React 开发机会点标注页面,作为独立模块嵌入平台,与主系统解耦。
- 对接腾讯位置大数据,按步行、骑行两种商圈口径获取并可视化人口、金融、客流数据。
- 通过 HTTP 接口把机会点和周边数据推送到第三方流程系统,打通"采集→补充→审批"。
- 基于飞书 OAuth 网页授权实现免登录进入。
- 用 Java 异步多线程开发批量取数工具,并发获取多个点位的周边数据。
- **R 结果**:已支持全国范围选址,批量取数替代人工逐点查询,提升了取数效率,免登录降低了业务人员使用门槛。
